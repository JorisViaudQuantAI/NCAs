# Paper replication workflow

The process used for this repository, written so that the next replication (any paper, any
budget) follows the same steps and ends up with the same kind of repository. Each step names
the file it produces. The order matters: nothing is trained before the claims and the budget
are written down, nothing is reported without three seeds and a figure.

## 0. Ground rules

- **Three seeds for every reported number**, always (mean and standard deviation, or min and
  max when only three values exist). A single run is a smoke test, not a result.
- **One figure per experiment**, drawn from result files on disk by one script, never from
  numbers typed by hand.
- **One command per result.** Every number in the results table can be regenerated by a command
  written next to it (see `docs/PAPER_MAP.md`).
- **Every departure from the paper is written down** the day it is made, with the reason
  (`docs/DEVIATIONS.md`). A deviation that is not written down does not exist for the reader
  and will be rediscovered painfully.
- **Validate at small scale first.** Everything runs on CPU on a toy size before any GPU time
  is spent: data loaders, model invariants, the training loop, the evaluation scripts, the
  figure script. GPU runs then only reproduce at scale what already works.
- **The repository must be readable without the paper open**: README, tutorial, paper map.

## 1. Read and extract the claims (`docs/PAPER_MAP.md`)

1. Read the paper fully, appendices included; the hyperparameter tables usually live there.
2. List every **claim** the paper makes with the figure or table that supports it. A claim is a
   sentence a reader could check: "accuracy keeps improving with more rollout steps",
   "confidence selection beats majority vote", "a model trained on 9x9 mazes solves 201x201".
3. For each claim, write down the **experiment** behind it: dataset, model size, training
   budget (steps, batch, sequence length), evaluation protocol (test set size, depth, trials),
   metric, and the paper's number.
4. Rank the claims: **headline** (the paper's main message), **mechanism** (ablations, why it
   works), **extra** (nice to have). Replicate in that order.

## 2. Set the local budget (compute budget table of `docs/DEVIATIONS.md`)

1. Measure, do not guess: time one training step and one evaluation rollout of each
   configuration on the target machine at the paper's sizes, then scale.
2. Fill the table *paper budget vs local budget* per experiment (steps, batch, model width,
   test-set size, trials K). Keep the paper's values wherever they fit; reduce the number of
   steps before reducing the model, and reduce the test set before reducing the model. State
   the expected effect of each reduction ("fewer steps: lower absolute accuracy, same trends").
3. Decide what is **out of scope** and say why (here: Visual Sudoku, full ARC).
4. Group experiments in **phases** that each produce a complete, publishable set of figures.
   Phase 1 is the cheapest set that already supports the headline claim.

## 3. Build the code, bottom up, with tests

Order: data loaders -> model (with invariant tests) -> rollout / evaluation -> training loop
-> experiment functions -> scripts -> figures. Each layer gets tests that run on CPU in
seconds (`tests/`). What the tests check here, and should check in any replication:

- datasets: shapes, token ranges, solvability, train/test disjointness, generator vs official
  format equivalence, augmentation correctness;
- model: parameter count against the paper, invariants the paper states (clamping of given
  cells, normalisation, padding behaviour, equivariances), finite gradients at singular inputs;
- rollout: shapes, reproducibility under a seed, chunking does not change results;
- training: a few steps run, checkpoints reload, resuming continues, the loss drops on a toy task.

Keep **configs** as YAML files that inherit from a base (`_base:`) and override only what
changes. The paper's values live in the base config with a comment; the local reductions are
the overrides, so the diff *is* the deviations list.

## 4. Run, in order (the "cheminement")

- A **phase script** (`scripts/run_phase*.sh` and `.ps1`) lists every command in the order to
  run it: train three seeds, evaluate, ablate, animate, aggregate, draw. It is idempotent:
  training resumes from checkpoints, evaluations whose output exists are skipped.
- Results are JSON files named `results/<experiment>/<task>_seed<k>.json`. Figures are named
  `figures/F<n>_<name>.png` with a fixed numbering.
- A **journal** of what was run, when, on what hardware, and what surprised us goes to
  `docs/DEVIATIONS.md` (deviations) and `docs/RESULTS.md` (numbers).

## 5. Aggregate and compare (`docs/RESULTS.md`)

`scripts/aggregate.py` reads every result file, computes mean and std over seeds, and writes
the comparison table against the paper's numbers, with a status per claim:

- **reproduced**: same conclusion and the paper's number within our dispersion (or within an
  amount explained by the budget reduction);
- **trend reproduced**: same direction and ordering, lower absolute numbers;
- **not reproduced**: different conclusion, with the best explanation we have;
- **not attempted**: out of budget, said so.

## 6. Write for the reader

- `README.md`: the idea in one paragraph, results at a glance, quickstart, what is where.
- `docs/TUTORIAL.md`: reproduce from scratch, in levels of increasing cost, with expected output.
- `docs/PAPER_MAP.md`: claim -> code -> command -> result file -> figure.
- `docs/DEVIATIONS.md`, `docs/RESULTS.md` as above.
- Animations or examples that show what the model does (here: the rollout GIFs).

## 7. Success criteria for a replication

A replication is **done** when: every headline claim has a status in `docs/RESULTS.md`
backed by three seeds and a figure; every deviation is journaled; the tutorial has been
followed end to end on a clean machine; and the tests pass in CI.

## Checklist to copy into the next replication

```
[ ] claims extracted with figure/table references          docs/PAPER_MAP.md
[ ] experiments table, paper budget vs local budget        docs/DEVIATIONS.md
[ ] phases defined, out-of-scope items named               README.md
[ ] data loaders + tests (official download + fallback)    src/.../tasks, tests/
[ ] model + invariant tests + parameter count check        src/.../model.py, tests/
[ ] training loop + resume + smoke run on CPU               src/.../train.py, configs/smoke_*.yaml
[ ] evaluation functions + scripts, one JSON per seed      src/.../experiments.py, scripts/eval_*.py
[ ] phase scripts (.sh and .ps1), idempotent               scripts/run_phase*.{sh,ps1}
[ ] aggregate.py (mean ± std vs paper) and make_figures.py scripts/
[ ] README, TUTORIAL, PAPER_MAP, DEVIATIONS, RESULTS       README.md, docs/
[ ] CI runs the tests                                       .github/workflows/tests.yml
[ ] 3 seeds for every number, figures regenerated           results/, figures/
```
